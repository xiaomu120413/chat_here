# Mobile LAN Verification Checklist

Date: 2026-05-08

## Preconditions

- PC and phone are on the same Wi-Fi/LAN.
- Windows firewall allows inbound TCP for the selected Gateway port, default `17321`.
- In the PC app, open `群聊详情 -> 移动网关`.
- Click `启动局域网 Gateway`.
- Record:
  - `手机` URL
  - `Token`

## Checks

## 1. Local PC Health

From PC:

```text
GET http://127.0.0.1:17321/api/health
```

Expected:

```json
{
  "ok": true,
  "service": "tauri-gateway",
  "mobileReady": true
}
```

## 2. Phone Health

From phone browser:

```text
http://<PC-LAN-IP>:17321/api/health
```

Expected:

- Page loads JSON.
- `ok` is `true`.

## 3. Token Required For Protected APIs

From phone or PC:

```text
GET http://<PC-LAN-IP>:17321/api/threads
```

Expected:

- `401`
- Error message: `missing or invalid gateway token`

## 4. Authorized API

Use an HTTP client that can set headers:

```text
Authorization: Bearer <Token>
GET http://<PC-LAN-IP>:17321/api/threads
```

Expected for current M11 Rust Gateway:

- Full thread API is not migrated into Rust Gateway yet.
- Protected unknown routes return `404 route not found`, not `401`.
- This confirms token validation path works.

Expected after full API migration:

- `200`
- JSON thread list.

## 5. Security Check

Expected:

- LAN mode only starts after clicking `启动局域网 Gateway`.
- Local mode binds to `127.0.0.1`.
- Token is generated by backend and not hardcoded in source.
- Stopping Gateway makes phone URL unreachable.

## Current Limitation

The Rust Tauri Gateway currently exposes `/api/health` and token-gated routing shell only.

The full thread/message/SSE API still exists in the tested Node Gateway module and must be migrated or hosted before phone can participate in the same thread.
